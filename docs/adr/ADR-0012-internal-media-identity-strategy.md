# ADR-0012: Internal Media Identity Strategy

Status: Accepted

## Context

Media 0.2 distinguishes Work, MediaEntity, Timeline, Asset, TechnicalRepresentation, MediaSource, Release, ReleaseGroup, Collection, Creator, and several identified relationships. Their identities must remain independent of external providers, persistence technology, and future wire formats.

ADR-0007 deliberately does not choose identifier formats or C# implementation details. Before implementation begins, Media needs a consistent internal identity strategy that prevents accidental interchange between different domain concepts while permitting creation and future rehydration.

## Decision

- Each HISPANIA entity or identified domain relationship uses a strongly typed internal ID appropriate to its concept.
- The underlying ID value is a 128-bit UUID.
- New IDs generated by HISPANIA use UUID version 7.
- Existing IDs may be rehydrated while preserving their exact stored value; they are not regenerated and are not required retrospectively to have been generated as UUID v7.
- Entities receive their IDs at creation or rehydration and do not depend on an ID generator.
- `IIdGenerator` is not part of Media Domain at this time. If later required, it belongs outside the domain in an application-level abstraction and is implemented by infrastructure.
- External identifiers remain provenance-bearing associations and never substitute HISPANIA internal identity.
- Persistence representation and wire/API representation are outside this decision.

## Alternatives Considered

- Use a plain `Guid`/UUID everywhere: rejected because it permits accidental interchange between unrelated domain identities.
- UUID version 4 for new identities: rejected because fully random insertion order is less suitable for common indexed persistence than UUID v7.
- ULID: rejected for now because UUID v7 keeps UUID/Guid interoperability without introducing a separate identifier representation.
- Numeric database-generated identities: rejected because identity would be coupled to a persistence implementation and unavailable before persistence assigns it.
- Require entities to generate their own IDs: rejected because creation and rehydration need to preserve an explicitly supplied identity.

## Consequences

- Cross-concept ID assignment becomes harder to express accidentally.
- UUID v7 provides approximately time-ordered creation values for newly generated IDs, but does not define business ordering or authorization semantics.
- Domain constructors and factories must support explicit IDs for future persistence rehydration.
- Future persistence, serializers, and APIs need explicit mappings for strongly typed IDs.
- UUID v7 generation time is not confidential information and IDs must not be treated as secrets.

## Related ADRs

- ADR-0007 defines the Media identity graph and leaves identifier strategy open.
- ADR-0011 establishes that external identifiers do not define HISPANIA identity.
