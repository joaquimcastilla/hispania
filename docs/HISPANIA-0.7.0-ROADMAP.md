# HISPANIA 0.7.0 stabilization roadmap

This roadmap has ten steps. Only **Step 1/10 — audit and architectural contracts** is in scope for this record. The remaining steps are planned work, not implemented features or accepted release claims.

| Step | Planned focus | State |
|---|---|---|
| 1 | Audit repository and PR #16; consolidate architecture boundaries, contracts and decisions | In progress; see `HISPANIA-0.7.0-STEP-1.md` |
| 2 | Make the Platform/Core build and hosting profile autonomous and validate Linux ARM64 resource needs | Not started |
| 3 | Define independently installable application packaging and dependency ownership gaps | Not started |
| 4 | Specify portable node identity, verified capabilities and worker enrollment evolution | Not started |
| 5 | Specify generic workload requirements and capability-based placement evolution | Not started |
| 6 | Specify execution lease, fencing, cancellation, failure and retry semantics | Not started |
| 7 | Specify authorized data source/destination grants and direct transfer protocol | Not started |
| 8 | Specify client-facing operation state and topology-transparent access | Not started |
| 9 | Add incremental architecture and cross-platform compatibility gates | Not started |
| 10 | Run release-level validation, reconcile documentation and make a go/no-go recommendation | Not started |

Sequence and scope for Steps 2–10 are proposals. Each requires its own review, evidence, and authorization before implementation. No step implies a stable release, merge, tag, or publication.
