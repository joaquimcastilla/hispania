# Security configuration

Production configuration is strict and local; remote HTTPS binding requires private TLS certificate material. HTTP is restricted to loopback. Use a verified TLS reverse proxy if external access is needed; disable unintended development exposure. Windows uses LocalService and Linux a non-root service identity under existing deployment policy.

## Authentication and requests

Login and bootstrap each consume the process-local socket-peer bucket: burst 20, sustained 20/minute (one token every 3 seconds). Login also consumes the normalized account/socket-peer pair bucket: burst 5, sustained 6/minute. Account names follow existing ASCII grammar (3–64, case-insensitive lowercase; trim surrounding whitespace). No global account lockout is imposed by remote failures. Shared NAT/proxy peers share budgets. Responses are 429 with integer-second `Retry-After` and safe `authentication_rate_limited`; no password verification occurs for a rejected request. Missing/wrong/disabled credentials return generic 401. Buckets expire after 10 minutes inactivity; 4096 total partitions; saturation rejects new partitions for up to 600 seconds instead of evicting live limits. Restart resets counters. These values are policy constants, not new serialized configuration fields.

No forwarded-header middleware is enabled. `X-Forwarded-For` and `X-Forwarded-Proto` cannot alter the effective IP/scheme; reverse proxy operators must budget for the proxy socket peer. Trusted proxy support is not implied. HSTS is not emitted from spoofable forwarded headers; the actual TLS terminator owns deployment HSTS policy.

Kestrel: 100 headers, 32 KiB aggregate headers, 8 KiB request line, 30 second header timeout, 120 second keepalive, framework default minimum body throughput. Login/bootstrap body maximum 8 KiB; bodies are bounded before binding, including chunked bodies via Kestrel's request-size feature. Other endpoints retain framework limits and their existing package/asset/protocol validation; do not configure a globally huge upload body limit. Passwords are 12–1024 characters for creation/change; login rejects >1024 without truncation. PBKDF2 remains HMAC-SHA256/600000 iterations/16 byte salt. Existing bounded historical iteration verification is retained.

Sessions use the `Authorization: Session ...` header, 32 random bytes encoded as 43 URL-safe characters and SHA-256 hash at rest. Concurrent sessions are allowed; logout revokes one. Disable-account atomically revokes all current SQLite sessions; re-enabling cannot resurrect them. Each validation reads current user status. Web stores the token in tab-scoped sessionStorage; token theft remains possible after browser compromise. Auth is not cookie-based, so ambient-cookie CSRF defenses are not indiscriminately added. No permissive credentialed wildcard CORS policy is installed. CSP remains same-origin executable scripts, no framing/objects/arbitrary contribution JS. `nosniff`, `DENY`, `no-referrer` and sensitive response `no-store` apply. CSP's inline-style allowance is existing Web behavior.

## Files, children and trust

`file:NAME` resolves only uppercase opaque references inside secrets/. Every resolve validates owner/ACL, size and all ancestor reparse points. Linux private files are 0400/0600 and directory 0700. Windows permits service identity, SYSTEM and Administrators. Environment provider requires operator provisioning and is plaintext in the process environment. Keep installation binary directories unwritable by the service identity. Backups require restricted operator storage; Linux staging/restore roots are 0700; Windows roots disable inherited ACLs and permit only the creating identity, SYSTEM and Administrators. The parent must be private before creation; privileged local link/ACL races remain outside the guarantee.

Use explicit trusted package IDs and publisher keys with signatures required; signed code still requires activation authorization. Restrict module/worker administration bearer material. Worker identity is SHA-256 certificate fingerprint associated with registered node ID and configured capability allowlist; inventory hints do not grant capabilities. OS/framework TLS defaults are retained; do not enable obsolete TLS manually. Resource limits use existing Windows Job Objects/Linux prlimit plus runtime timeouts/concurrency. Linux process count containment and inherited child environment must be assessed against actual OS behavior, not described as a sandbox. Use structured executable argument lists; media tools receive controlled local streams.

Database connection credentials use references, not logs. Configure PostgreSQL TLS and access controls for its actual network boundary. Backups do not encrypt secrets/state or authenticate provenance. No new serialized format/version axis is introduced by these controls.

ModuleHost, local/distributed FFmpeg worker launch policies and FFprobe remove `HISPANIA_SECRET_*` from the child environment. PATH, platform/runtime variables, the per-launch ModuleHost token and FFmpeg protocol parameters remain. This narrowly targets the production secret provider; arbitrary operator environment variables are not a guaranteed secret-free allowlist. Children retain the service identity and may access its readable files. PostgreSQL tools deliberately receive their required DB credentials through the existing environment mechanism.
