# Explicit historical data capture

This opt-in tool is excluded from the solution and CI. Its HistoricalRoot must be a new archive of commit `78f291fdacf9442c6e2d8e23094dc0e309828693`, never the current checkout. Keep the archive's Directory.Build.props/Directory.Packages.props and referenced production projects. Production/build inputs were verified against that commit (172 files, no differences).

1. Archive the exact source to a disposable directory and verify its production inputs against Git.
2. Build Capture.csproj with `/p:HistoricalRoot=<absolute archived root>`.
3. Run the built executable with a NEW staging directory. Existing directories are rejected. It invokes archived constructors and EF migrations, generates archived PostgreSQL schema SQL and writes synthetic playback state through the archived writer.
4. Run `python populate.py <staging>`. This adds deterministic TEST ONLY rows to the historical schemas and refuses a second population. Sessions/passwords are synthetic, not credentials from an installation.
5. Run the executable with `--verify <staging>` using old readers to check credentials, content handles, coordinator payload and native Media IDs/manual metadata. Do not accept a fixture that only the new reader can consume.
6. Close all old readers, checkpoint/truncate WAL and normalize standalone SQLite files before initial review. Build semantic snapshots and a separate manifest with hashes; inspect values and provenance. Only a human-reviewed NEW baseline may be published. Never overwrite `compatibility/data/0.7/` to repair a current regression.

The frozen corpus is already checked in. Normal tests consume copies; data-compatibility-manifest.py is read-only and its negative harness uses temporary copies. Reproduction can differ at the byte level because historical constructors create incidental timestamps; exact checked-in hashes, not regenerated byte equality, identify this reviewed capture. UUIDs in EF SQLite are native GUID TEXT despite BLOB declarations. PostgreSQL SQL is the archived migration script plus deterministic data, executed by the live test rather than by the capture tool.

See ../../docs/PHASE-16-HISTORICAL-DATA-UPGRADES.md for the initial capture correction, hash list and invariants.
